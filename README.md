# LLM Arena · 星穹格斗场

五位拟人选手，独立选择形象与决策控制器，在原创 Three.js 庭院里进行同时出招的策略格斗。内置策略不需要密钥；配置服务商后也可选择真实模型。服务端先计算完整系列赛，浏览器再按正常速度连续演出，不让网络等待打断动作。

支持选招、自创招、原因气泡、意图解说、侦察、条件连招、回合复盘、换边系列赛、能力统计、天梯，以及暂停、0.5×/1×/2×、三种机位、音效、重播和最近8场本机记录。空格暂停/继续，R重播，1/2/3切换机位；切换浏览器标签页自动暂停。本机记录包含完整回放，回看不会再次请求真实模型。浏览器存储空间不足时，当前页面仍可重播。

## 启动

需要 Node.js 22+ 和支持 WebGL 2 的现代浏览器。Three.js 使用本机依赖，不依赖 CDN。

```sh
npm ci
npm start
# http://127.0.0.1:3000
```

首页为格斗；原有井字棋/四子棋保留在 `/classic`。角色为原创程序化卡通模型，形象参考 [AI Girls Atlas](https://github.com/HABAI182/ai-girls-atlas)（ZipZipPipe；DeepSeek 原角色署名上善无形），未复制上游图像或模型素材。

## 规则概览

### 观众复现：边缘与失误硬直

在比赛设置中填写“比赛种子”（留空仍随机），点击开始即可观看真实服务端计算的回放：

- **边缘**：左侧形象/控制器选 Grok / 内置策略 grok，右侧选 DeepSeek / 内置策略 deepseek，1局，种子 **2**。第3回合第23拍，DeepSeek退至8格；右侧HUD显示“擂台边缘 · 8格”，距离芯片、解说和战报同步标记。边缘且近距时显示“被逼角”。
- **失误→硬直**：左侧形象 GPT、控制器“故障演练 · GPT（偶发非法招式）”，右侧 Claude / 内置策略 claude，1局，种子 **2**。第1回合第1拍即发生非法招式，HUD显示原因，角色垂头硬直而非举盾。该可选控制器每7次实际决策中第1次提交非法招式，其余使用GPT策略；计划照常执行，所有错误经过相同裁判校验。默认控制器和内置天梯不使用故障演练；手动比赛以独立控制器ID记账。

可用0.5×或暂停观察，重播/本机历史保留相同结果。超时使用同一硬直渲染路径，显示“决策超时”；故障演练只注入非法招式，不人为拖慢服务器。

- 九格战场（0..8），从2/6格开始，不重叠、不交叉。距离1为近、2–3为中、4+为远。边缘被重击、投技、绝技命中额外受5伤害。
- 每回合100生命/体力，能量从0开始。每拍体力恢复10、能量恢复4；命中加8能量，格挡加5，资源上限100。每局三局两胜、每回合最多30拍，耗尽生命或时间到按剩余生命判胜。
- 双方隐藏提交，再同时结算。快招打断慢招，同速互击；投破格挡/招架；招架反击近身打击，闪避躲重击/投射物；重击有抗刺拳装甲。启动加上前一拍的恢复硬直。距离变化可能导致落空。
- 先各禁一招，再各选4个可选招、1个绝技、设计1个自创招。自创招预算：`2×伤害点 + 速度点 + 中距2点 + 远距3点 ≤ 10`；必须包含近距。伤害=`4+3×伤害点`，启动=`5−速度点`，体力=`14+4×伤害点`。非法设计由裁判替换并记失误。
- 佯攻骗防成功加15能量，并使对手下一拍多1硬直；休息恢复25体力，但休息/佯攻/失误硬直被打多受25%伤害。侦察后，本回合可见对手能量、招式与自创招；观众始终看到完整资源。
- 每局24次深度决策。最多3步条件计划由平台执行，不调用控制器、不消耗思考预算。预算用尽后只允许快招。非法输出、抛错和超时当拍眩晕，下一拍加2硬直。
- 第6/14/22拍生成恢复道具，持续6拍；第10/20拍生成两格危险区，持续5拍，每拍造成6伤害。场地由种子确定。
- 系列赛可选1/2/4局，第二局及以后轮流换边，禁招顺序随之交换。每回合后复盘；后续局及同一控制器组合的后续比赛可读取精简历史。

内置脑：GPT均衡读招、Claude招架反击、Gemini抢攻、DeepSeek侦察控距、Grok混沌佯攻。它们仅从裁判给出的视图做决策，不读取对手隐藏提交。内置比赛是启发式策略基线，不能把形象名称当成同名真实模型的能力评测。

## 控制器接口

`controller = { id, label, async draft(view), async decide(view), async review(view) }`。
所有控制器经过同一裁判验证。默认裁判期限15秒，预算耗尽后5秒；`runSeries({ ..., deadlines:{normal,quick} })` 可在测试中注入短期限。

每拍只传入视图（对手能量/招式/自创招在未侦察时为null）：

```json
{
  "round": 1, "turn": 4, "turnsLeft": 27,
  "you": {"hp": 90, "stamina": 88, "energy": 36, "cell": 3, "lag": 0, "loadout": ["strike", "heavy", "parry", "blast", "nova"], "custom": {}, "budgetLeft": 20},
  "opponent": {"hp": 85, "stamina": 90, "cell": 4, "lag": 1, "energy": null, "loadout": null, "custom": null},
  "distance": 1, "band": "near", "edge": [false, false],
  "stage": {"items": [], "dangers": []},
  "recentMoves": [], "legalMoves": [{"id": "jab", "name": "刺拳", "ranges": ["near"], "stamina": 14, "energy": 0, "damage": 5, "startup": 1, "quick": true}],
  "plan": [], "memory": [], "reviewNotes": [], "rulesSummary": "规则摘要"
}
```

决策返回：

```json
{"move":"throw","reason":"预判对手防守，用投技破防","predict":"guard","plan":[{"if":"near","then":"jab"}]}
```

`reason`为最多40字的一句话；`predict`为对手招式ID或类别；`plan`可省略。条件为`always/opponent_guarded/hit/missed/was_hit/near/mid/far`；下一步不满足条件或招式不合法就丢弃计划、重新决策。

选招阶段先`draft({phase:"ban",pool,...}) → {ban}`，再`draft({phase:"pick",pool,bans,ultimates,...}) → {picks:[4个ID],ultimate,custom:{name,damage,range:["near"],speed},reason}`；其中damage/speed是购买点数。回合后`review(包含完整本回合日志的视图) → {notes,adjust}`。完整回放包含动作、事件、资源、格子、预测、原因、计划标记、失误、场地、中文解说与统计。

## HTTP API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/fighters` | 公开形象资料 |
| GET | `/api/controllers` | 内置策略及已配置真实模型；不含密钥 |
| POST | `/api/fights` | `{players:[id,id],controllers:[id,id],games:1或2或4,seed?:无符号32位整数}` → `202 {id}` |
| GET | `/api/fights/:id` | `{status:"running"或"done"或"error",progress:{game,round,turn},replay?,error?}` |
| GET | `/api/ladder` | 按控制器累计胜负、胜率、失误率、预判/佯攻命中率、回合间提升 |
| POST | `/api/ladder/run` | `{games?:2}` → `202 {id}`；五个内置脑两两对战，每对1–20局 |
| GET | `/api/ladder/run/:id` | 天梯任务进度/结果，也可用比赛轮询路由 |

POST只接受本站JSON请求。真实模型对局最多同时1场，与经典棋局共享限制；最多保留20个任务。仅完成的比赛计入天梯，服务商错误中止的不计。战绩与每对控制器最近12个精简局摘要最佳努力保存到被git忽略的`data/ladder.json`；磁盘不可写时仍可用内存战绩。重启不保留任务回放。

能力统计按累计计数加权；回合间提升同时显示各自伤害份额和类别预判率的平均变化（百分点）。预判只统计实际提交的预测：`predictionExactHitRate`要求招式ID完全一致；`predictionCategoryHitRate`（页面展示，亦为`predictionHitRate`）在ID一致或类别一致时命中。类别为`attack/throw/defend/move/feint/scout/rest`，格挡、招架、闪避、屏障统一归入`defend`；预测具体招式时也按它所属类别计分。旧天梯保留胜负等历史，但新的精确/类别预判率只从升级后的比赛累计，不把旧评分混入新口径。连招执行会显示计划步号、条件和招式。

## 自动联赛

服务启动即运行联赛（`LEAGUE=off`关闭）：五名选手单循环，每场两局换边系列赛，胜3分、平1分；一轮循环为一个赛季，结束时产生冠军，前两名晋级、后两名降级（青铜→星穹六段）。等级分为国际象棋Elo（初始1500，K=32，按每局结算）。比赛在后台提前计算、按时间轴“直播”：首页显示赛程、积分榜和正在进行的比赛，进入直播会从当前进度开始播放3D画面；赛间45秒、赛季间90秒。

首页的「赛前竞猜」可为每场未开赛的联赛投票，并查看双方票数；猜中积1分、猜错中断连中，平局和取消不计分。进入同一场联赛直播的观众可发送和接收实时弹幕，也可在本地隐藏。观赛工具可开启浏览器中文语音，文字解说始终可见；完赛后可播放或跳过3D高光集锦，打开已完赛的联赛回放也可直接看高光。这些功能不需要模型密钥。

每名选手默认使用内置策略，与真实模型走同一回合接口；`LEAGUE_ROSTER=gpt=openai:模型ID,...`可替换为已配置的真实模型控制器。内置战绩只用于验证框架，真实模型加入前用`POST /api/league/reset`（需`Authorization: Bearer $LEAGUE_ADMIN_TOKEN`）清空联赛、回放与天梯。状态与最近400场回放保存在被git忽略的`data/league/`。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/league` | 当前赛季赛程、积分榜、直播/下一场、上赛季冠军与升降级、全部等级分 |
| GET | `/api/league/matches?season=&fighter=` | 回放库：已完成及直播中的比赛 |
| GET | `/api/league/matches/:id` | 比赛信息与完整回放（直播中亦可） |
| GET | `/api/league/fighters/:id` | 选手档案：战绩、能力雷达、等级分走势、交锋记录、赛季记录 |
| POST | `/api/league/reset` | 管理员重置联赛 |

页面：`/fighter?id=gpt`选手档案，`/replays`回放库，`/?match=<id>`直接观看某场联赛。

## 真实模型配置与限制

复制`.env.example`为`.env`并填写密钥/模型ID，然后：

```sh
node --env-file=.env server.js
```

`OPENAI_API_KEY` + `OPENAI_MODEL`启用OpenAI Responses；`ANTHROPIC_API_KEY` + `ANTHROPIC_MODEL`启用Anthropic Messages。模型ID支持英文逗号分隔。`MODEL_TIMEOUT_SECONDS`控制服务商期限，但格斗请求不超过裁判15秒/快招5秒；经典棋局默认30秒。

**真实模型格斗已实现，并通过模拟请求测试，但未使用真实密钥验证。** 单次服务商失败记当拍失误；连续3个决策回合服务商失败会中止系列赛，并提示密钥/访问权限/模型/额度/连接错误，不计天梯。合法连接返回非法招式仍记失误，而不是服务商故障。经典棋局仍通过NDJSON输出，非法落子判负，连接错误中止。

密钥仅在服务端使用，不要提交`.env`。真实模型按回合调用，产生费用。默认只监听本机；不要向不受信任的用户公开加载密钥的实例，共享部署前需要鉴权和用量限制。
